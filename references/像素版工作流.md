# 像素版工作流（v4 像素剧场，旧做法）

> 只在用户点名要「像素版」「五段式」「完播优先 30–45 秒」时用。默认做法见 SKILL.md（海螺 H3 ＋ 问题链 ＋ LibTV Seed Audio）。
> 这一版的配音走豆包直连（`scripts/seed_voice.py`）；画面由代码逐帧画（`scripts/pixel/`）。下文原样保留 v4 的流程，「## 工作流」里的命令仍然可用。

用户说一个书里的内容，你交付一支能直接发的竖屏科普动画：**三只单色像素猫（大比、胜利、大宝）在人类日常的情境里把概念演出来，按费曼学习法讲给一个完全不懂的朋友听；镜头角度一直在变，字是清楚的涂鸦手写字，60–120 秒讲明白。**

猫是演员，演的是观众自己（已读不回就脑补、开会不敢说真话、怕别人看自己、拖延……）。故事是虚构的；**概念、实验、数字和原因都以书为准**，而且说清是人类研究。

你同时是编辑（读书、核实）、编剧（费曼脚本）、导演（镜头和动作）和剪辑（出片、审片）。用户没要求，就不中途停下来问；只在真正需要用户决定时才问（书里找不到这个概念、用户的话有两种理解）。平台没说就做抖音。

## 依赖与首次准备（像素版）

- `uv`、`ffmpeg`。画面用 numpy＋Pillow 逐帧画（uv 自动装），**CPU 占用低**，一分半的片子约 3–5 分钟渲完。
- **配音：豆包音频生成（seed-audio-1.0）**。三只猫和旁白各有固定的设计音色，按每句的情绪念。需要豆包语音控制台的 API Key（放 `~/.config/cat-social-psych/keys.env`，一行 `DOUBAO_SPEECH_API_KEY=...`；不是火山方舟 `ark-` 开头的 key），约 1 元/分钟，**会把口播稿发给火山引擎**。第一次用先生成声音样本：`python3 $S/scripts/seed_voice.py design 角色库/角色.json`（出 `角色库/声音试听.mp3` 给用户听）。没有 Key 时加 `--no-voice` 出无声片和字幕，之后用剪映配。
- 查书用 PyMuPDF＋RapidOCR（本地运行，不联网）。
- **机器配置低**：一次只跑一件重活（出片、整本 OCR 不要同时跑）。
- 下文的 `S` 指本 skill 目录（`~/.claude/skills/cat-social-psych`）。

## 项目目录

默认在当前工作目录下建 `猫说社会心理学/`（用户指定了就用用户的）。**第一次用时把 `$S/assets/角色库/` 整个复制到项目根目录**（里面有配音要用的声音样本），之后所有集共用：

```
猫说社会心理学/
├── 角色库/                    角色.json ＋ 大比/胜利/大宝/旁白 的声音样本
├── 进度.md                    已做集数：日期｜章｜概念｜主角｜场景｜时长｜成片路径
└── 18_第3章-基本归因错误/
    ├── 脚本要点.md            费曼五段 × 情境演出 × 镜头角度
    ├── film.py                口播 LINES ＋ 镜头函数 ＋ 音效 ＋ 发布信息
    ├── build/                 中间文件（配音缓存：同一句不重复扣费）
    └── output/                成片.mp4 · 字幕.srt · 口播稿.txt · 抽帧.jpg · 预览.jpg
                               封面_竖屏_3x4.png · 封面_横屏_4x3.png · 封面_9x16.png
                               发布文案.md（抖音：标题＋爆款简介）· 发布文案_小红书.md · 发布文案_视频号.md
```

## 工作流

### 1. 定位

读 `references/书目索引.md`，把用户的话对到「章 → 概念 → 经典研究 → 故事点子」（每章标题后面有页码范围；这一版的译名以书为准，如焦点效应、规划谬误、自我妨碍）。再看 `进度.md`：避免重复，**主角和上一集换一只猫**。用户给一整章，就挑这章还没做过的概念做一集，并告诉用户这章还能拆哪几集。

### 2. 读书（每一集都要做）

```sh
B="uv run --with pymupdf --with rapidocr_onnxruntime python $S/scripts/book.py"
$B search 基本归因错误 --chapter 3     # 找到概念在哪几页
$B read --book-pages 104-106          # 读那几页的全文
$B page 104 --book --out <临时目录>/p104.png   # 看原页（OCR 缺字、核对数字）
```

OCR 偶尔认错字、正文和页边栏会混在一起：**上屏的数字和要引用的原话，用 `page` 看原图核对**。从书里取：定义、书里举的例子（常常就是最好的生活类比）、经典实验（谁、怎么做、结果）、原因和条件、书里点破的常见误解。用自己的话转述，注明页码。

### 3. 写费曼脚本（读 `references/费曼脚本.md`）

**默认写完播优先版（30–45 秒，film.py 加 `PACE = 'fast'`）**：时长预算、悬念留到最后、1.5–3 秒换镜头，见 `费曼脚本.md` 开头。

五段，顺序不能乱：**① 钩子**（反问 / 反常识 / 数字 / 冲突，≤ 20 字）→ **② 痛点共鸣**（观众心里那句话）→ **③ 本期承诺**（看完得到什么）→ **④ 正文**（大白话；术语当场翻译；一个能演出来的生活类比；纠正一个常见误解；一个能用的办法）→ **⑤ 收尾**（一个好回答的问题，或自然引出下一期）。

先写 `脚本要点.md`：每一行 = 段落 | 口播 | 情境演出 | 镜头角度。**每一句都要写得出猫在做什么**；写不出动作的句子是在念书，改掉。故事用三只猫的性格（大比脑补、胜利吹牛翻车、大宝唱反调），读 `references/角色设定.md`。

### 4. 找背景照片（默认用像素化的真实照片当背景）

按脚本里的场景（客厅、走廊、办公室、教室……）各找一两张：

```sh
uv run --with pillow python $S/scripts/fetch_images.py "living room night" --no-cat --kind photo --no-sa --n 6 --out <集目录>/素材/图
```

Read 预览图挑图：**画面里不能有认得出的人脸、品牌、店名、文字招牌**；关键词用英文。`--no-sa` 只留 CC0 / 公有领域 / CC BY（不用 CC BY-SA）。CC BY 的作者和授权写进 `META['sources']` 和抖音简介的 `source`（署名在 `素材/图/credits.json`）。找不到合适的照片，就用纯色或手画背景。

### 5. 写镜头脚本 film.py（读 `references/像素剧场.md`，照着示例 film.py 写）

- `LINES`：口播，每句标 `part`（钩子 / 痛点 / 承诺 / 正文·术语翻译 / 正文·生活类比 / 正文·纠正误解 / 正文·办法 / 收尾）、`mood`（决定旁白语气），角色台词写 `who`。
- 每个镜头一个函数，动作卡在配音时间轴的词上（`T['id'].at('词')`）。**至少 4 种角度**（远景、特写、过肩、俯视、侧面、主观、分屏、取景器、特写→拉远），登记在 `ANGLES`。
- 少用图表：能演出来的不画图；一集最多一张。
- `SFX(T)`：每个弹出、转折、揭晓配一个音效。`BGM`：全片一段铺底，不切换。
- 背景：`fr.photo(照片, fx=, dark=, tint=, blur=)`，自动像素化、减色、调明暗；猫要碰的东西（手机、食物、开关）仍然画像素。
- `META`：爆款封面模板 `cover=dict(line1=, line2=, hi=, who=, expr=, emote=, bg=, tag=)`（竖 9:16、竖 3:4、横 4:3 自动各排一版，不截静帧）、出处、抖音的 `douyin`（三个标题＋爆款简介＋话题＋置顶评论），其他平台的标题和简介。读 `references/抖音发布.md`。

### 6. 自检（出片前）

```sh
X="uv run --with numpy --with pillow --with scipy --with soundfile --with skia-python python $S/scripts/pixel/build_pixel.py"
$X <集目录>/film.py --check                  # 费曼五段、类比、术语翻译、误解、钩子长度、绝对化用词、角度、时长、抖音标题和简介、横封面
$X <集目录>/film.py --no-voice --preview     # 每句一帧的总览 output/预览.jpg（不调配音、不花钱）
```

用 Read 看 `预览.jpg`，对照下面的自查清单改，改到没有问题再出片。

### 7. 出片（后台运行）

```sh
$X <集目录>/film.py [--platform 抖音|视频号|小红书] [--no-bgm]
```

先配音（豆包，新句子每句约半分钟），再逐帧画、混音（人声 + 铺底配乐自动避让 + 音效，−14 LUFS）。全片超过 120 秒会亮黄灯：删一两句重跑（配过的句子有缓存）。

三个平台用同一支成片，只是封面比例和文案不同。出完抖音版后，其他平台不用重渲：

```sh
$X <集目录>/film.py --publish-only --platform 小红书    # 几秒钟：重出 3:4 封面和 发布文案_小红书.md
$X <集目录>/film.py --publish-only --platform 视频号
```

### 8. 审片

先看出片日志里的**视听节奏自检**（全文在 `build/qa/节奏.txt`），有黄灯就改到没有。出片时会逐帧检查三件事：

- 切镜时还在说话（话没说完就换画面）；
- 一闪而过、短于 0.7 秒的镜头；
- 字幕或名牌压在猫身上（猫的脚要踩在 y≤334 的地面线上）。

这些是用户看片时最先觉得「卡、乱」的地方，见 `references/线条画风.md`「地面线和字幕带」。

再 Read `output/抽帧.jpg`（每句一帧）、`封面_竖屏_3x4.png` 和 `封面_横屏_4x3.png`（大字够大、关键词标黄、主角表情清楚、九宫格里一眼能认出是这个系列）；读一遍 `发布文案.md` 的爆款简介；ffmpeg 量一下响度；读一遍 `字幕.srt` 和 `口播稿.txt`。日志里出现「念出来和稿子不一样」时，改写那一句重跑。

### 9. 交付

告诉用户：成片路径和时长；封面（抖音电脑端上传竖封面 3:4 ＋ 横封面 4:3，手机 App 和视频号用 9:16，小红书用 3:4）；`发布文案.md` 里的标题和爆款简介（把简介原文贴给用户）；其他平台的发布文案文件；用了书里哪几页；有没有黄灯和理由。在 `进度.md` 记一行，建议下一集（按书的顺序，换一只猫当主角）。发布时在「作品声明」勾选「内容由 AI 生成」。

## 自查清单（出片前、出片后各对一遍）

**内容（费曼）**
1. 第一句就是钩子（反问 / 反常识 / 数字 / 冲突），第一帧就有角色和冲突。
2. 痛点是观众自己的生活；承诺具体；正文里术语当场翻译、有一个演出来的生活类比、纠正了一个误解、给了一个能用的办法；收尾自然。
3. 书里的事实都带页码；数字换成人能感受到的说法；不说「一定」「所有人」「100%」「科学证明」。

**画面**
4. 三只猫按性格演（大比怂、胜利吹牛、大宝唱反调），故事是人的日常。
5. 至少 4 种镜头角度；每一句都有动作或镜头变化；没有一张图停超过 3 秒。
6. 图表最多一张；能演出来的都演出来。
7. 字都是涂鸦手写字、带白描边，手机上看得清；上屏字少（气泡 ≤ 8 字、贴纸 ≤ 6 字）。
8. 主角的脸和重点不在平台按钮区（右侧中下）和底部 380 以下。

**发布**
9. 封面用爆款模板：上行 ≤ 8 字、大字 ≤ 7 字且有一个标黄的词、主角大头表情夸张、左上角和左下角不放字；竖 3:4 和横 4:3 都看过。三个标题带搜索词；爆款简介首句是钩子、有干货、有问题、话题 3–5 个；CC BY 照片的署名在简介里。

**节奏（完播）**
10. 30–45 秒；第 0.1 秒开口；钩子的答案在最后 5 秒；1.5–3 秒换一个镜头；结尾不念互动和下期。

**声音**
11. 配乐是一段浅浅的铺底，从头到尾不停；音效踩在画面事件上；角色台词是角色自己的声音。
12. 响度约 −14 LUFS，配音没有念错。
